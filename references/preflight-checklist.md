# 交付前检查表

**每次交付都填一遍。** 逐项标「已查 / 未查 / 不适用」。交付时把这张表一起给出去——用户从表上就能看出覆盖面，不用追问「哪几轴没查」。

> **脚本通过不等于表达层通过。** 脚本覆盖词句与句式，叙事姿态、文体适配、叙事弧三轴只能人工过。把「✅ 全过」当成整轴完成，是这类自检最常见的失败。

## 第 0 步：定文体（不填完不动手）

| 项 | 填 |
|---|---|
| 文体 | 幻灯片 / 讲稿 / 论文 / 综述 / 标书 / 审稿意见 / 回复信 |
| 读者 | 谁看，看完要做什么 |
| 交付形态 | 终稿 / 草稿 / 只给诊断 |

**文体没定就查，判据会混用**：幻灯片要求书面自足（每处引用点名），讲稿允许口语节拍（可提纲式）。混着查会同时产生误报与漏报。

## 一、五轴

| # | 轴 | 查什么 | 机检能帮到哪 | 状态 |
|---|---|---|---|---|
| 1 | **叙事姿态** | 有没有替听众预设质疑、自我辩护、元评论；限定与否定是否压过正面内容 | 组 6、10–17、26 给候选 | ☐ |
| 2 | **词句层** | 套话、抽象标签、伪对立、长句、缩写、提示语冒号、翻译腔 | 组 1–9、18–21 覆盖 | ☐ |
| 3 | **段落层** | 一段一点；工程协议腔；中英混杂；边界压过动作 | 组 22、25、27 | ☐ |
| 4 | **章节层** | 每节是否在写它该写的内容 | 无，人工 | ☐ |
| 5 | **文体适配** | 幻灯片书面自足；讲稿口语可念 | 无，人工逐页 | ☐ |
| 6 | **身份匹配** | 所定身份的人写得出这句吗 | `check_persona.py` 给可疑 | ☐ |
| 7 | **叙事弧** | 每页有没有转折与落点 | 无，人工 | ☐ |

## 二、内容层四查（只报，不改）

| # | 查什么 | 状态 |
|---|---|---|
| 8 | **引用幻觉**：这篇文献存在吗，原文支持这句吗 | ☐ |
| 9 | **论断越界**：动词的强度与证据匹配吗 | ☐ |
| 10 | **数字漂移**：同一个数跨节一致吗，口径写了吗，**层级对吗**（组间 / 关联 / 增量 / 个体） | ☐ |
| 11 | **定位虚设**：引用的位置（Table 2 / 摘要 / 全文）与说法一致吗 | ☐ |

## 三、收尾

| # | 项 | 状态 |
|---|---|---|
| 12 | **对抗承压**：列出可被攻击的点，逐个标「已回应 / 未回应」 | ☐ |
| 13 | **定量审计**：每个数字标「已核 / 待核 / 口径」 | ☐ |
| 14 | **全局一致性**：设备、参数、时长更新后 grep 全目录，历史文件同步了吗 | ☐ |
| 15 | **AI 边界**：需要声明吗，口径是什么 | ☐ |

## 交付时怎么报

```
表达层：轴 1–7，已查 7，未查 0
内容层：4 处只报未改（位置 / 类型 / 问题 / 核验）
承压：3 个缺口已补进追问表
一致性：grep 关键词 2 个，历史文件 1 处未同步（已标注）
```

**报了「已查」就必须能说出查过什么。** 说不出来的，标「未查」。
