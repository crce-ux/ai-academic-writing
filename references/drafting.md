# 起草 · 定贡献 → 骨架 → 分节 → 润色

> **管什么**：稿子还没写出来、或刚写出来时的事——主张什么、怎么搭、按什么顺序写、润色到什么程度。
> **不管什么**：写出来之后的核查（见 `content-audit.md` 与 `verification-chain.md`）。

---

## ① 定贡献（**不可跳**）

**动笔前先回答三句话**：

1. 这篇论文**主张什么**？（一句话，不用「探讨」「分析」这类动词）
2. 它比现有文献**新在哪**？
3. **证据够不够**支撑这个主张？

> 🔴 **贡献定不了就别动笔。**
>
> 与课题设计里的**证伪条件**是同一条纪律。定不了贡献的稿子，
> 写到 Discussion 一定会漂：没有一个东西在对齐你写下的每一句。

**AI 在这里能做什么**：帮你把贡献**逼问清楚**（追问、找反例、比对你说的"新"是否真新）。
**不能做的**：替你决定贡献是什么。

---

## ② 搭骨架

**IMRaD**（多数原创研究）：

```
Introduction  为什么做（问题 + 缺口）
Methods       怎么做（可复现）
Results       发现了什么（只报不说）
Discussion    意味着什么（含局限）
```

**骨架阶段要定死的三件**：

- [ ] **主图 / 主表是哪几个** —— **先定图表，再写文字**
- [ ] 每个结果**对应哪个假设**
- [ ] **局限有哪些**（主动列，不等审稿人问）

> ⚠️ **「先定图表」是一条论证纪律。**
> 图表一旦定下，Results 就只能报这几件事——写不出多余的话。
> 反过来先把文字写完再配图，一定会出现「图配不上文」或「文里说了图里没有的东西」。

---

## ③ 分节撰写

**推荐顺序：Methods → Results → Introduction → Discussion。**

理由：**Methods 和 Results 最客观**，先把硬事实落定，
再写 Introduction 时就不会为了"讲故事"而拔高贡献；
Discussion 放最后，因为它的每一句都该能指回前两节。

| 节 | 只做一件事 | 最常见的越界 |
|---|---|---|
| **Methods** | 让人能复现 | 写成了 Results（夹带结果） |
| **Results** | 报，不说 | 写成了 Discussion（夹带解释） |
| **Introduction** | 问题 + 缺口 | 写成了综述（引用堆砌、无收口） |
| **Discussion** | 意味着什么 | 写成了摘要复述（无新信息） |

> ⚠️ **Results 里夹带解释**是最高频的一处——「A 组高于 B 组，说明……」。
> 「说明」之后的都该在 Discussion。**Results 只报，不说。**

**AI 在这里能做什么**：起草、改写、换句式、把要点铺成段落。
**纪律**：AI 写出的每一句**事实性内容**都要回到证据——见 ⑥⑦。

---

## ④ 润色

**润色的唯一界限：不得改动事实。**

| 不许动的 | 为什么 |
|---|---|
| **数字** | 改一个数字就是造一个事实 |
| **单位 / 分母** | mg vs μg、ITT vs PP——改了结论就变了 |
| **方向词** | 增/减、优/劣——反了就是反结论 |
| **专有名词 / 术语** | 换个近义词可能换了概念 |
| **限定词** | 「在 X 人群中」删掉就变成普适结论 |

> 🔴 **润色改动若触及上表任一，一律回退原样。**
> 宁可留着不流畅的句子，不要一个读起来很顺但数字错了的句子。

**AI 在这里能做什么**：句子层面的流畅度、语法、搭配。
**不能做的**：动上面五类。**发现它们有问题，只报不改**——走 ⑦ 的流程回原文核。

---

## 四步之间的关系

```
① 定贡献  ──→  决定后面所有节的取舍
                    ↓
② 搭骨架  ──→  定图表 = 定 Results 的边界
                    ↓
③ 分节写  ──→  顺序反了，贡献就会被"讲故事"带跑
                    ↓
④ 润色    ──→  只动语言，不动事实
                    ↓
              （写完了 → 进 ⑤⑥⑦ 核查）
```

贡献定歪了，后面每一节都会替它圆场——圆场留下的痕迹，正是 ⑤ 表达层要抓的「防御性写作」。
